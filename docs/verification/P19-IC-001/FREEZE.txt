A COUNTING TRAP THIS MILESTONE ALREADY FELL INTO
------------------------------------------------

Recorded here because the same trap is available during the run. The author's
first mutation sweep reported a test failing on a tree with no mutation in it.
The cause was the harness, not the code: shutil.copy2 preserves mtimes, so a
restored file looked OLDER than the object compiled from the mutated one, ninja
skipped the rebuild, and a STALE BINARY carrying the previous mutation produced
a failure that was not there.

Same family as the three incidents this project already carries — `ctest -R`
matching nothing and exiting 0, a hyphen-stopping regex that counted 4 of 16,
and an `inherits[0]` walk that read -Werror as off. The rule that follows:
a number is not evidence until the thing that produced it is known to be the
thing under test.

Started 21:47:35 on 2026-11-05 and died at 23:32 the same evening, part way

What the stage record shows:

    debug-ext         configure 0, clean 0, build 0, no-op rebuild 0, ctest 0
                      100% tests passed out of 6240, 2559.63 s
    release-ext       configure 0, clean 0, build 0, no-op rebuild 0
                      ctest exit 1073807364 = 0x40010004, killed at test
                      5589 of 6240, every test to that point Passed
    debug-shared-ext  configure exit -1073741205 = 0xC000026B
    repeats           selected 0 tests and were counted as FAILED stages

THE CAUSE IS IN THE EXIT CODES, not in the code under test. 0x40010004 is
DBG_TERMINATE_PROCESS -- the process was killed, it did not fail -- and
0xC000026B is STATUS_DLL_INIT_FAILED_LOGOFF, which a process gets when it
starts while the window station is shutting down. The client restarted
(the session's scratchpad path changed with it) and took the process tree with
it. No test failed and no stage reported a defect.

THE REPEAT STAGES FAILING IS THE GUARD WORKING. Both selected 0 tests against
a build tree that no longer existed, and qualify.cmd counted each as a failed
stage rather than letting ctest's "No tests were found!!!" pass as success.
That is the P19-DOF-001 attempt-1 lesson holding under a condition nobody
arranged.
