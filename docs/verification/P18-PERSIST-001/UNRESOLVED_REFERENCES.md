# P18-PERSIST-001 — a GeometryReference is preserved, never resolved, never rebound

```text
FaceName("a face that does not exist")  ->  save  ->  load  ->  the SAME FaceName
The reader receives no document, no regenerator and no mesher. There is nothing for an unresolved reference to be rebound TO.
```

## What the canonical reference is in P18

`FaceName { ObjectId feature; FaceSelector face; }`, with `FaceSelector { role, entity, along, alongSketch, edge, copies }`. It is the **only** canonical target of a surface heat flux and of both boundary-condition kinds (a volumetric source has none). The brief's second variant, `NamedBoundarySet`, is a P16 *mesh* concept and is not a thermal target in P18-DATA; there is no such variant to persist ([AUDIT.md](AUDIT.md)).

## Every selector form round-trips

`GeometryReferencesSurviveExactlyInEveryForm` puts one `FaceName` of each form the data model accepts on a **load and a condition** (eight of each) and compares the loaded face with the original field for field, and by description:

```text
start cap                                       role = StartCap
end cap                                         role = EndCap
side face of a profile entity                   role = Side, entity
side face swept along a path edge               role = Side, entity, along
... in another sketch                           role = Side, entity, along, alongSketch
chamfer face                                    role = Chamfer, edge
a copied face (two copies, IN ORDER)            role = EndCap, copies = {(feature 9, 1), (feature 10, 2)}
a face of a feature that does not exist         feature 987654, role = Side, entity 77
```

## Unresolved is intent, and it stays unresolved

`AnUnresolvedReferenceIsPreservedAndNotRebound` adds a load and a condition on a side face whose entity no face is generated by (`entity 9991`) to the golden analysis:

1. **It really does not resolve before the save** — the derived chain stops with a diagnostic and produces no result — or the test would be about nothing.
2. After the round trip both records are **still there** (4 loads, 3 conditions: not dropped), carry the **same** selector (`entity == 9991`) and the same value (500 W/m²), and the selector still names its entity rather than becoming a default-constructed face.
3. **Not rebound:** every face the body actually has — start cap, end cap, and all four sides — is compared by name, and none equals the loaded reference. Each is a face it could have been rebound *to*.

`AnUnresolvedReferenceStillRefusesTheSolveAfterLoading` is the other half: the loaded analysis, remeshed through the normal path, makes the derived chain stop with a diagnostic, produces no post result, and its validation report is `Fail`. Persistence preserved the intent; refusing is the chain's job; the reference was not "made to work".

## Malformed is not the same as unresolved

`AMalformedReferenceIsNotTheSameAsAnUnresolvedOne` — the distinction is about the *representation*:

| Input | Outcome |
| --- | --- |
| a role this build does not know | **refused**, at `…boundary_conditions[0].face` |
| a side face naming no entity | **refused** by the selector's own rule |
| a reference that is not an object | **refused** |
| a condition with no `face` key | **refused**, naming `face` |
| a `node` / `element` / `facet` / `dof` / `node_id` / `element_id` key where a reference belongs | **refused** as an unknown key, by name — a mesh-local target is never read |
| a well-formed reference to a face that does not exist | **LOADS**, carried as unresolved intent |

## The invalid feature handle: the one rule this file adds

The data model's `validate(ThermalLoad / ThermalBoundaryCondition)` checks the face *selector* but accepts a `FaceName` whose feature is the invalid default handle (`FaceName{}`). P18-CMD-001 found this and made the **command layer** refuse it. The file does the same at its own boundary: `face.feature: 0` is refused as **"a target must name a feature; the invalid feature handle is not a face that is missing but a record that names nothing"**, at `…loads[0].face.feature` / `…boundary_conditions[0].face.feature`. The data-model behaviour itself is left alone (it is P18-DATA's qualified behaviour) and is recorded as observation O2 of P18-CMD-001.

The line is deliberately the same as the commands': a valid handle that names no feature (`555555`, `987654`, `424242` for a control) is *intent whose target does not exist yet or any more*, and loads; the invalid handle is not a target at all.

`DanglingTargetsAreIntentAndAnInvalidFeatureHandleIsNot` also pins, for the owner, that a **meshing control** handle that names no object — or an object of another kind — loads (the document does not check dependencies on load, for any object type) and is refused only later, by `requireThermalModel`, with a diagnostic.

## No nearest-face repair, structurally

The reader's signature is `(const Json&, std::string name, std::string_view path)`. A nearest-face search needs a mesh, a geometry map or at least a document; it cannot be written in this file without first adding a parameter, and gate rule 9 fails a thermal persistence file that names a `Document`, `findObject`, `modifyObject`, `resolve*` or `regenerat*`. Mutation PER36 (a load face rebound to the end cap on read) and PER13 (rebound on write) are both killed ([MUTATIONS.md](MUTATIONS.md)).
