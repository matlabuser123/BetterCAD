## DEFECTS SUSPECTED (code contradicting a requirement as literally written)

No hard contradiction of B1-B11 was found. Items where code and requirement text diverge, most important first:

* **D1 (low) silent time-grid snap.** `ThermalTransient.cpp:370-376` accepts `t_end/dt` within 1e-9 relative of an integer as "whole steps", runs N full steps of `dt`, and reports the final sample time as the user's `t_end` (`timeAt(index >= steps_)` returns `end_`, `:385-393`). The integrated span differs by up to 1e-9 relative. The grid exposes `integratedSpan()` (`ThermalTransient.hpp:220`), but a grep shows it is read nowhere except tests: no report, balance or validator finding mentions it. B10 says "no silent correction". Documented and tested (`ThermalTransient_TimeGridToleranceBoundary`), but not disclosed to the user.
* **D2 (scope) NamedBoundarySet not a thermal target.** B6 lists FaceName/NamedBoundarySet; `src/thermal` and `include/bettercad/thermal` contain no `NamedBoundarySet` (0 grep hits). Loads and conditions take a `FaceName` only.
* **D3 (low) anchoring classifier is row-relative.** `ThermalSolve.cpp:311` decides a region is anchored iff some row has `|sum| > 1e-10 * sum|row|`. A genuinely weak but valid Robin anchor (`hA/(kL)` below 1e-10, e.g. `h = 1 W/m^2K`, element size 1e-8 m, `k = 400`) would be refused as `MissingTemperatureDatum`/`UnanchoredThermalRegion` rather than solved. Tests prove a 1e-6 anchor works and 3e-16 noise does not, nothing between 1e-10 and 1e-6 is probed.
* **D4 (info) literal `abs` on det J.** `ThermalElement.cpp:248` `std::abs(det) > B` contradicts "NO abs(detJ)" only on a grep; it is a magnitude gate against the rounding bound, orientation (`:256`) and volume (`:293`) use the signed value.
* **D5 (info) no absolute per-step transient residual** (B10.8): only the two normalized ratios are stored per step.
* **D6 (low) duplicated constants.** `kSymmetryTolerance` (`ThermalSystem.cpp:47`) and `kEffectiveSymmetryTolerance` (`ThermalTransient.cpp:38`) are two independent 1e-13 literals; the solver-settings defaults (1e-9, 1e-12) exist in `linalg/SymmetricSolve.hpp:62,65`, `ThermalData.hpp:307,310`, `StructuralData.hpp:332,350`; the balance policy expression is written inline in `ThermalBalance.cpp:206`, `:698-699`, `ThermalValidation.cpp:940`. They agree today; nothing forces them to keep agreeing.
* **D7 (info) h = 0 policy differs by layer:** canonical convection requires `h > 0` (`ThermalBoundary.cpp:567`), the kernel/seam accept `h >= 0` (`ThermalConvection.cpp:75`, `ThermalBoundary.cpp:303`). Intentional and documented/tested in `ThermalBC_ZeroConvectionCoefficientPolicy`.
* **D8 (info) bare-algebra seam accepts a zero-capacity node that conducts** (`ThermalTransient_ZeroCapacityConnectedByConductionSolves`); not reachable from the production chain (see B10.10).
