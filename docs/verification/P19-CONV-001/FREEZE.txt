THE DIFFERENCE FROM P19-DIV-001, WHICH IS THE POINT
---------------------------------------------------

P19-DIV-001 REACHED A FREEZE, A LAUNCH AND A PASS WITH NO INDEPENDENT REVIEW,
and recorded that as its own first defect: the reviews were run afterwards,
found five code defects and eight suite defects, and the three-hour
qualification had to be thrown away and run again from clean.

THIS MILESTONE RAN BOTH REVIEWS BEFORE THIS FREEZE. Two independent reviewers
read the tree without seeing each other or this author's conclusions — one
against the implementation, one against the suite — and returned 25 findings
between them. Every one was verified against the code before being accepted,
and the serious ones were fixed BEFORE this file was written. That is the whole
reason there is no attempt 1 to preserve here.

The two reviews converged independently on two findings, which is the strongest
signal either produced:

  * the row-sum identity's PRESCRIBED INFLOW term was never non-zero in any
    test of that identity. The test's own comment claimed "a mixture:
    prescribed inflow at some facets, zero-gradient at others" while binding a
    boundary that makes every facet zero-gradient, so the term was provably
    `+ 0.0` on every iteration — and the structural error ADR-072 Decision 5
    exists to prevent (a relative 0.9995 on 15% of cells) was not reproducible
    by the suite at all.

  * the public header promised a refusal the code does not perform:
    "its stamp, its cell count or its boundary-face count disagrees", while
    `problemOf` compared only the boundary-face count. That made this operator
    strictly WEAKER than the one it cited as precedent, and a boundary prepared
    against a different mesh with the same facet count was silently accepted.

WHAT THE REVIEWS FOUND THAT CHANGED THE CODE

  F1  NO OWNER/NEIGHBOUR RANGE GUARD, and here the unvalidated index is used
      for WRITES. `CellIndex{}` is `SIZE_MAX` and `topology.owner` returns it
      for a face it does not hold, so `pattern[owner].push_back(...)` and
      `source[owner] -= ...` could write at `SIZE_MAX`. P19-DIV-001 carries
      this guard and its comment records that a review forced it there; this
      operator had none, which is that correction REGRESSED one milestone
      later. Now phase 3.
  F4  the conditional stamp check, restored to P19-DIFF-001's form.
  F5  `ResultIsNotFinite` was a catch-all for three faults that are not
      non-finiteness — a symbolic-pass miss, any `fromCsr` refusal, a missing
      neighbour. Split out as `AssemblyIsInconsistent`.
  F6  the three reported flow totals escaped the finiteness gate, so an
      assembly could succeed with `outflow == +inf` while every coefficient was
      finite. Now inside it.
  F9  `input.component` was never validated and indexes a three-element array;
      a cast can produce a value outside the three. Now `ComponentOutOfRange`.
  F11 the producer's `kind` switch had no guard, so a seventh boundary kind
      would silently inherit a WALL'S EXACT ZERO — the inverse of the leak
      Decision 2 exists to prevent. Now a static_assert on the kind count.

WHAT THE REVIEWS FOUND THAT CHANGED THE PUBLISHED CLAIMS

  ADR-072 DECISION 8's TRANSPOSE IDENTITY WAS FALSE AS WRITTEN, in two
  independent ways. `A(-phi) == A(phi)^T - diag(div phi)` was derived from the
  UPWIND scatter rule and then stated unqualified; a central share is geometric
  and does not swap, failing by `phi(2w-1)` per face, and a ZeroGradient or
  Symmetry boundary face carries its full `phi` on the diagonal, failing by
  `phi_b`. Re-measured: Upwind with FixedValue boundaries 19.25% bit-exact at
  worst 4.36e-16; Upwind with ZeroGradient 0.00% at worst relative 1; Central
  0.00% at worst 2.1 to 2.7. The original measurement had NO CENTRAL BRANCH and
  modelled every boundary face as FixedValue, so it was of a model narrower
  than the claim.

  ADR-072 DECISION 7's DOMINANCE IDENTITY WAS MISSING THE PRESCRIBED INFLOW
  TERM — Decision 5's own correction, repeated one paragraph later in the
  neighbouring decision. And re-measuring found A THIRD CONDITION neither the
  review nor the ADR had stated: the deficit uses `|a_ii|`, so once backflow
  drives the diagonal negative the identity breaks whatever the inflow term is.
  The scope is `a_ii >= 0`, which makes `backflowFaces` the identity's validity
  condition rather than a diagnostic beside it.

  ADR-072 DECISION 6 AND THE HEADER BOTH CLAIMED "a compile-fail case holds the
  asymmetry" AND NOTHING HELD IT. The compile-fail group's five enumerated
  claims are about other things, and no compile-fail case could express this
  one: it is a runtime branch. Both claims removed and the absence recorded.
