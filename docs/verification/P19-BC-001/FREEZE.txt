THE PRE-FREEZE REGRESSION, AND ITS ONE FAILURE
----------------------------------------------

An ad-hoc full ctest on debug-ext, before the freeze:

    6183 / 6184 passed      3819.53 s
    1 failed:  cli.new.unicode-path

THE COUNT ARITHMETIC IS EXACT, checked against a number written down before
this milestone began rather than by scanning for the absence of the word
"fail":

    6120   P19-DOF-001's qualified count, from its own evidence
    + 48   unit.CfdBoundary_          (ctest -N: 48)
    + 16   compile_fail.cfdbc.        (ctest -N: 16)
    = 6184                            (ctest -N: 6184)

THE FAILURE IS THE INVOKING SHELL'S CODE PAGE, NOT THE TREE, and that is
measured rather than asserted. The CLI wrote the correct bytes -- the file on
disk contains "name": "Platt with a-ring and a check mark" correctly -- and
CMake decoded the child's stdout through the OEM code page, so the regex saw
mangled text where the CLI had emitted UTF-8. The same test, the same build and
the same binary PASS when re-run under chcp 65001:

    cmd /c 'chcp 65001 >nul & ctest -R unicode-path'   ->  1/1 Passed

This is P19-DOF-001's recorded known limitation L6: tests/cmake/RunAndCheck.cmake
calls execute_process(... OUTPUT_VARIABLE) with no ENCODING argument. qualify.cmd
pins chcp 65001, so every qualification is unaffected; an ad-hoc ctest from an
OEM shell is not. Unchanged here, because that is shared test infrastructure and
outside this milestone's authorized scope. No source or test file was changed
for it, and the freeze is not void.

A NOTE ON THE FIRST ATTEMPT TO MEASURE THAT
-------------------------------------------

The first command written to re-run the test under UTF-8 had its regex eaten by
shell quoting and printed "No tests were found!!!" -- and would have exited 0.
That is exactly the defect tests/cli/ZeroMatchGuard.cmake exists to prevent, met
by accident while verifying something else. The filter was checked with ctest -N
first (Total Tests: 1) before the result above was believed.

EXPECTED COUNTS, WRITTEN DOWN BEFORE THE RUN
-------------------------------------------

So the logs can be read against a number rather than for the absence of the
word "fail" -- which is the lesson P19-DOF-001's first attempt taught, where a
repeat stage ran 352 tests instead of 2991 and passed every one of them:

    full suite, per preset      6184   = 6120 (P19-DOF-001) + 48 unit
                                       + 16 compile-fail, exactly
    repeat set, per preset      3039   = 2991 (P19-DOF-001) + 48 matching
                                       unit\.Cfd, exactly
    repeat markers per log     15195   = 3039 x 5

Both reconcile with no remainder. All 48 unit cases fall in the repeat filter
(it carries unit\.Cfd) and none of the 16 compile-fail cases do (the filter
carries no compile_fail prefix), which is why the two sums differ by exactly 16.
Verified with ctest -N against the frozen tree before the run.
