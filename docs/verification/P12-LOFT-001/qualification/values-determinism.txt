Cross-configuration comparison of the measured values of the P12-LOFT-001 tests.
Each configuration's bettercad_tests.exe ran the test cases the selector "[loft][p12]" matches with
-s --reporter xml --rng-seed 1; values.py filtered the report; compare-values.py (in this directory) compared
the results. Temporary paths and document UUIDs are normalized; lines holding a pointer value are dropped.

RESULT: every value measured from the geometry kernel is identical in all three configurations.

Debug and Debug-shared agree byte for byte. Release differs on eight lines, and on every one of them the
number that differs is a constant the TEST computes, not a value read back from a solid. All eight are
downstream of one expression in tests/core/geometry/LoftShapeTests.cpp:

    double mixedPolygonCircle(int n, double radius, double circumradius) {
        const double k = static_cast<double>(n);
        return 2.0 * k * k * radius * circumradius / pi * std::pow(std::sin(pi / k), 2.0);
    }

which -O2 evaluates two units in the last place away from -g: 254.64790894703247659 in Release against
254.64790894703259028 in Debug, either side of the exact 800/pi = 254.64790894703253343. The four entries
compare that constant, or one derived from it (the halfway area, the prismatoid volume), against a value
written out by hand, so the tool reports the differing number as the "measured" side; it is not. The other
four entries are volumes read back from the kernel, and in those the measured number is IDENTICAL in all
three configurations -- only the expectation beside it moves:

    LoftShapeTests.cpp:505               measured 6764.39617963917589805 in all three
    LoftShapeFeatureTests.cpp and        measured 4058.63770796589460588 in all three

No solid, volume, area, centroid or bounding box differs between configurations. The comparison follows.
