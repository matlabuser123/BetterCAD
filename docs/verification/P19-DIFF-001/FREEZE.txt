    apps  include  src  tests  examples  cmake  CMakeLists.txt  CMakePresets.json

TODO.md, ROADMAP.md and docs/ are OUTSIDE it, deliberately: documentation
written after the run cannot affect the executable or the tests, so it cannot
void the qualification. Anything under the eight paths changing after this
point DOES void it, and the run starts again from clean.

THE METHOD IS QUALIFY.CMD'S OWN, not `git rev-parse HEAD:<path>`: a scratch
GIT_INDEX_FILE, `git read-tree HEAD`, `git add -A` over the eight paths,

the two files. The same commands the harness runs, so the identities it records
during the run are comparable with these without translation.

WHAT THE MUTATION SWEEP IS WORTH, STATED PRECISELY
--------------------------------------------------

The adversarial review PREDICTED that eight specific source-vector mutations
would survive the suite as it then stood, and the fix pass claimed to close
them. All eight are killed. That is a prediction and a measurement rather than
an assertion, which is the only reason the number means anything.

Three of the twenty probes were VOID on the first sweep because they did not
compile -- `unused variable ... [-Werror=unused-variable]`, reproduced by hand.
That is P18-ELEM-001's recorded finding F3, and its remedy was applied:
reformulate so the mutated code still uses every name. Counting them as
survivors would have claimed three gaps that do not exist; counting them as
kills would have claimed three verifications that never ran.

One probe was MIS-PAIRED by the author: a wrong neighbour DIAGONAL was tested
against the bit-exact symmetry assertion, and a diagonal cannot be asymmetric.
Re-paired with the row sum, which is what a wrong diagonal breaks.

And ONE REAL GAP was found, which is the sweep's own finding and not a review's:
`AFaceVaryingGradientIsReadAtItsOwnFace` could not detect a hard-coded face
index, because `isInternal(face)` is `face.value() < internalFaces` and the
fixture's only contributing face was therefore index 0. The test was repaired to
make six more faces contribute, and the mutation then died -- attributed to
exactly the one case whose name claims it.

COUNTING TRAPS THIS MILESTONE ALREADY FELL INTO
-----------------------------------------------

Recorded here because the same traps are available during the run. Every one was
the author's measurement and not the code's.

  (i)   a verification regex requiring exactly eight leading spaces missed the
        LAST case of each compile-fail foreach block, because that one ends with
        a closing paren on the same line. It reported 18 of 22 registered. The
        registration was correct; the check was not
  (ii)  backslash levels were silently halved passing a script through a shell
        heredoc -- four in the source arrived as one -- so a guard block built
        with `\\.` would have been written with `\.`, a CMake wildcard where a
        literal dot was meant. The generator was rebuilt to construct both
        backslashes from chr(92), immune to any escaping layer
  (iii) `timeout 110` on a build killed the LINKER and reported
        `ld returned 143`, which reads like a link error and is a signal
  (iv)  an UNQUOTED shell heredoc let bash execute the backticks inside a C++
        comment, mangling it into the test file. Quoted heredocs only
  (v)    a batch script invoked an executable by a forward-slash path, which
        cmd.exe cannot resolve, and produced an empty measurement that looked
        like a successful run. The measurement was redone directly

Same family as the four this project already carries -- `ctest -R` matching
nothing and exiting 0, a hyphen-stopping regex that counted 4 of 16, an
`inherits[0]` walk that read -Werror as off, and P19-IC-001's shutil.copy2 mtime
artefact that made a stale binary report a defect that was not there. The rule
that follows: a number is not evidence until the thing that produced it is known
to be the thing under test.
