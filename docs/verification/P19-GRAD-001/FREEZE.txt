THE FROZEN SURFACE
------------------

    apps  include  src  tests  examples  cmake  CMakeLists.txt  CMakePresets.json

TODO.md, ROADMAP.md and docs/ are OUTSIDE it, deliberately: documentation
written after the run cannot affect the executable or the tests, so it cannot
void the qualification. Anything under the eight paths changing after this point
DOES void it, and the run starts again from clean.

THE METHOD IS QUALIFY.CMD'S OWN, not `git rev-parse HEAD:<path>`: a scratch
GIT_INDEX_FILE, `git read-tree HEAD`, `git add -A` over the eight paths,
`git write-tree --prefix=<dir>/` for each directory, and `git ls-files -s` for
the two files. The same commands the harness runs, so the identities it records
during the run are comparable with these without translation.

WHAT THE VERIFICATION IS WORTH, STATED PRECISELY
------------------------------------------------

THE FIRST MUTATION PASS KILLED ONLY 10 OF 20, and four of the seven survivors
were real defects in the suite. Closing them took it from 33 cases to 39. Two
probes are retired rather than killed, each with a reason: one is IMPOSSIBLE
(`CfdGeometry::skewness` returns nullopt at a boundary face by ADR-065 Decision
6's design, so there is no boundary skewness for a mutation to leak in), and one
probed DEAD CODE that was deleted rather than tested (`normalSystem` returns its
system now, so a system accumulating across cells is unrepresentable).

ONE PREDICTION WAS CONTRADICTED. ADR-070 Decision 6 claimed the least-squares
weights cannot affect linear exactness; the sweep was given that as a prediction
and killed the mutation, twice. The mathematics holds in exact arithmetic; the
mutation changes the normal matrix's SCALING, so the conditioning and the
rounding error rise past a bound tight enough to see it. The decision says so
now.

TWO INDEPENDENT REVIEWS FOUND FOUR BEHAVIOURAL DEFECTS, which is more than
either P19-IC-001's or P19-DIFF-001's reviews found: a non-finite gradient
returned as a SUCCESS, a diagnostic that refuted itself, an out-of-bounds read
guarded only by a frozen table in another module, and a constant-mode flag whose
stated reason was false. All four are fixed and each has a test. One test is
DELETED, because it never called the operator at all, and half of another was
cut for asserting a property of its own helper.

AND REPLACING A TRANSCRIBED ORACLE WITH AN INDEPENDENT ONE FOUND A FIFTH. The
suite's conditioning oracle was a line-for-line copy of the function it checked.
A cyclic Jacobi diagonalisation disagreed, and the textbook trigonometric form
for the SMALLEST eigenvalue proved wrong by a factor of 3.2 at a conditioning of
1e12 and, worse, reported a positive-definite matrix as having a non-positive
eigenvalue -- a FALSE REFUSAL of a solvable cell. The smallest eigenvalue comes
from the invariants now, by a cancellation-free quadratic, still closed-form. The
flat-cell sweep's split changed from 4-refused/1-solved to 3-refused/2-solved as
a direct result, and both figures are in the evidence.

COUNTING TRAPS THIS MILESTONE FELL INTO

Recorded here because the same traps are available during the run. Every one was
the author's measurement or the author's test, not the code.

  (i)   COUNTING TRAP (i) FROM P19-DIFF-001'S FREEZE RECURRED VERBATIM. A script
        reported 20 compile-fail cases registered against the 24 written, because
        its filter dropped the LAST case of each foreach block -- that one ends
        with a closing paren. The registration was correct and the check was not,
        exactly as last time. The two are compared as SETS now, not counts
  (ii)  a tolerance stated relative to the ANSWER measured 4.16e-11 against a
        1e-12 bound at an offset of 1e6. The code was right: that is
        eps * offset / (|g| |d|), P18-ELEM-001's finding F4
  (iii) three compile-fail gates failed because GCC emits "invalid
        initialization of reference" for a reference bound to the wrong type,
        which the expected-diagnostic regex did not list. Same family as (i)
  (iv)  every compile-fail probe also emitted -Werror=missing-declarations, so
        each could exit non-zero for a reason unrelated to its claim. The helpers
        are `static` now, and each case emits exactly one diagnostic
  (v)   a constant-field test at 0.0, and then at 17.25, could not see an
        unstable interpolation -- zero because both forms give zero, and 17.25
        because it is 69/4 and both products are exact. A search over 200,000
        candidates found 16 % that discriminate; the constant is 12345.6789
  (vi)  a "largest magnitude" case asserted the answer exceeded the FIRST cell's,
        and on RM-MESH-01 the first cell IS the maximum
  (vii) a per-body threshold of "more than 10 internal faces" failed on
        RM-MESH-01, which has exactly 6. The claim moved to the aggregate
  (viii) the first two 40-hex strings in run-qualification.cmd are NOT the
        preflight hashes, and taking them for the pair would have "verified" the
        wrong two files. All five are read by label now
  (ix)  a shell heredoc broke on quoting for the EIGHTH time this session.

Same family as the six P19-DIFF-001 recorded. The rule that follows is
